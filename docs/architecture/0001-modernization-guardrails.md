# ADR 0001：现代化改造的安全与兼容红线

## 状态

已接受，2026-07-24。

## 背景

RustForge 已经具备 MITM 抓包、被动规则、AI 分析、任务树、Repeater 和报告闭环。后续需要升级这些模块，但安全工具中的一次边界回退可能比普通功能缺陷更严重，因此先固定所有后续实现必须遵守的架构约束。

## 决策

### 1. 授权判断只能由后端执行

所有能够向目标建立连接或发送请求的路径都必须经过同一个后端 Scope 策略。前端禁用按钮、提示和二次确认只负责交互，不能作为授权边界。

没有当前项目、Scope 为空或目标不匹配时，系统采用拒绝策略。未来若支持重定向或工作流，每个新目标都必须重新判断。

### 2. 保持人在回路

规则和 AI 只能产生待验证假设、解释和建议。主动重放必须由用户明确触发；系统不得自动利用目标，也不得因为模型或规则命中而自动把 Finding 标记为已确认。

### 3. 捕获流量和模型输出均视为不可信数据

HTTP 头、正文、URL、模型输出和导入的规则包都必须经过大小限制、结构校验和安全转义。来自目标的文字不能改变系统指令或授权策略。

### 4. 最小化敏感数据披露

API Key 不得返回前端或进入普通设置导出。发送给外部模型和写入报告的内容默认脱敏，并记录实际披露范围。日志不得输出秘密、完整认证头或 CA 私钥。

### 5. Finding 与 Evidence 分离

规则或 AI 结果表达“假设”，Evidence 表达可追溯的实际观察。Finding 只有在人工接受至少一条 Evidence 后才能成为已确认状态。

### 6. 持久化格式必须版本化

数据库、规则包、提示词和知识标准都必须携带版本。当前未发布数据库先建立 v1 基线；首次公开发布后的数据库变更使用事务化迁移和迁移前备份，不通过删除旧数据解决兼容问题。

### 7. 安全失败采用可见的保守降级

Scope 无法判断、秘密迁移失败、规则包无效、AI 输出无法校验或 Evidence 关联失败时，系统停止对应动作并给出可诊断原因。不得静默放行、静默丢数据或伪装为成功。

## 影响

- 后续模块需要复用共享策略和版本化模型，前期代码量会增加。
- 部分旧接口会经过兼容层逐步迁移，不能一次性删除。
- 测试必须覆盖拒绝路径、迁移失败和敏感数据泄露，而不仅是正常功能。
- 新功能只有在保持上述约束并通过自动质量门禁后才能合并。
