# RustForge 首页“继续项目”改造设计

**日期：** 2026-07-23  
**状态：** 已确认，待实施计划

## 目标

将当前重复顶部导航、缺少实际用途的“工作台”改为简洁的项目续接页。首页首先帮助用户回到当前授权测试的最近工作区，其次帮助用户快速切换到最近项目。视觉参考 CC Switch 首页的留白、轻量边框和列表层级，但保留 RustForge 的深色专业工具风格。

## 已确认决策

- 首页首要职责是“继续当前项目”，不是模块导航或全局仪表盘。
- “继续”进入该项目最近使用的工作模块；没有历史记录时进入流量页。
- 主体采用“当前项目焦点卡 + 最近项目列表”。
- 焦点卡显示三项紧凑统计：流量总数、任务完成进度、待确认发现数。
- 不展示大图表、趋势图、全局统计或重复的模块入口。
- 最近项目最多显示 5 个，当前项目不在列表中重复出现。
- 代理状态继续由顶部栏统一展示，不在首页焦点卡中重复。

## 页面结构

首页移除：

- “工作台”大标题及说明；
- 当前项目/代理状态的两行状态表；
- 与顶部导航重复的五个模块入口。

首页主体采用约 `760px` 的内容宽度并靠页面上部居中，包含以下内容。

### 当前项目

小型分区标签“当前项目”下展示一张焦点卡：

- 项目简称标记；
- 项目名称；
- 目标主机；
- Scope 条目数；
- 最近工作区名称；
- 相对最近打开时间；
- 主按钮“继续{工作区名称}”。

焦点卡底部是一条三等分统计带：

1. 流量总数；
2. 已完成任务数 / 任务总数；
3. 状态为 `pending` 的待确认发现数。

统计使用数字和短标签，不使用独立大卡、图表或装饰性图形。

### 最近项目

焦点卡下展示“最近项目”列表：

- 按最近打开时间倒序排列；
- 排除当前项目；
- 最多显示 5 个；
- 每行显示项目简称、名称、目标主机、最近工作区、相对时间和“继续”操作；
- 没有最近项目时隐藏整个分区，不显示空卡片。

### 无项目状态

没有任何项目时只显示一个聚焦空状态：

- 简短说明 RustForge 以授权项目组织测试数据；
- 引导用户点击右上角的 `+` 新建项目；
- 首页不重复提供新建项目按钮或项目创建弹窗。

## 视觉语言

- 沿用现有主题 Token，不在组件中写死深色值。
- 深色主题为主要视觉基准：基础背景、单层面板、细边框、青绿色状态/主操作。
- 当前项目卡使用轻微强调边框与极淡的主题色背景，不使用大面积渐变或强阴影。
- 最近项目使用 CC Switch 风格的连续列表容器，以分隔线代替独立悬浮卡片。
- 主按钮使用主题强调色；橙色仍只用于顶部新建项目 CTA。
- 动效仅用于背景、边框和按钮状态，时长沿用 `--rf-duration`。
- 键盘焦点必须可见；整行可点击时仍保留明确的按钮语义和可访问名称。

## 最近工作区记录

新增轻量的前端持久化状态，建议键名：

`rustforge.workspace-history.v1`

数据结构：

```ts
type WorkspaceHistory = Record<
  string,
  {
    path: "/traffic" | "/repeater" | "/tasks" | "/findings";
    openedAt: number;
  }
>;
```

规则：

- 仅记录流量、重放、任务树和发现四个项目工作区；
- 首页和设置不更新记录；
- 当当前项目 ID 或路由变化且二者都有效时，更新对应项目记录；
- 项目没有记录时，继续路径默认为 `/traffic`；
- 最近项目先按记录中的 `openedAt` 排序；没有记录的项目追加在后并按 `created_at` 倒序；
- 无法解析、版本不兼容或引用不存在项目的本地数据应被忽略，不影响应用启动。
- 没有历史记录时显示“尚未打开”；目标主机为空时显示“未设置目标”。

## 数据流

### 页面进入

1. 项目 Store 已在 `App.vue` 挂载应用壳前完成加载。
2. `HomeView` 根据当前项目计算焦点卡和最近项目。
3. 当前项目存在时并行读取三项统计。
4. 每项统计独立完成；部分失败不影响其余数据与继续操作。

### 统计来源

- 流量总数：`countTraffic(projectId, {})`；
- 任务进度：`getTaskTree(projectId)` 后计算 `status === "done"` 与总数；
- 待确认发现：`listFindings(projectId, { status: "pending" })` 的条目数。

首页直接调用这些只读 API，不复用模块页面 Store 的筛选状态，避免首页加载覆盖用户在流量、任务树或发现页的上下文。

快速切换项目时，统计响应必须与发起请求的项目 ID 对比；过期响应不得覆盖新项目数据。

### 继续项目

1. 用户点击当前项目或最近项目的“继续”；
2. 若目标不是当前项目，先等待 `project.select(id)` 完成；
3. 从历史记录解析目标路由，无记录时使用 `/traffic`；
4. 导航到目标路由；
5. 选择或导航失败时保留当前页面并显示错误消息。

## 组件与职责

### `HomeView.vue`

- 渲染焦点卡、统计带、最近项目和空状态；
- 监听当前项目变化并加载统计；
- 执行项目切换和继续导航；
- 处理统计的加载、部分失败和过期响应。

### 最近工作区状态模块

- 封装本地存储的读取、校验和写入；
- 提供记录访问、查询继续路径和排序最近项目所需的数据；
- 不负责路由跳转或项目选择。

### `AppShell.vue`

- 监听当前项目与路由；
- 在进入有效项目工作区时调用最近工作区状态模块记录访问。

### `ProjectCreateDialog.vue`

- 从 `AppTopbar.vue` 抽取现有项目创建表单与提交逻辑；
- 通过 `v-model` 控制显隐；
- 由顶部 `+` 调用，首页空状态只提供文字引导；
- 创建成功后保持现有行为：刷新项目列表并选中新项目。

## 加载与错误状态

- 统计加载时在原位置显示轻量骨架或固定宽度占位，避免卡片跳动。
- 单项统计失败时该项显示 `—`，其他统计正常显示。
- 项目切换或导航失败时显示 Element Plus 错误消息，不清除现有页面。
- 本地历史记录损坏时静默回退到流量页，并在下一次有效访问后覆盖错误记录。
- 当前项目为空但项目列表非空时，显示选择项目提示和最近项目列表，不擅自选择项目。

## 响应式行为

- 正常桌面宽度保持单列、约 `760px` 主体。
- 宽度不足时，焦点卡主信息和继续按钮换行，按钮占满可用宽度。
- 三项统计优先保持一行；极窄宽度允许改为单列或两列。
- 最近项目的次要元信息可换行，但项目名称和继续操作必须保持清晰。

## 验证

### 场景检查

- 无项目；
- 有项目但没有当前项目；
- 单个当前项目；
- 多项目且包含/不包含历史记录；
- 当前项目切换；
- 四个工作区分别被记录并恢复；
- 设置和首页不覆盖最近工作区；
- 应用重启后历史记录仍可恢复；
- 三项统计为空、加载中、部分失败和全部成功；
- 快速切换项目时不会显示旧项目统计；
- 深色与浅色主题均可读；
- 当前桌面窗口尺寸及窄窗口下无横向溢出；
- 键盘可聚焦并触发所有主要操作。

### 工程检查

- 运行前端生产构建；
- 检查改动文件的 IDE/Lint 诊断；
- 不引入新的 UI 或状态管理依赖；
- 当前仓库没有前端测试框架，本次不为单页改造额外引入测试依赖。

## 非目标

- 新增全局数据仪表盘；
- 新增趋势图或图表库；
- 修改 Rust 数据库结构；
- 修改流量、重放、任务树或发现页面本身；
- 重做顶部导航；
- 增加项目删除、归档或搜索功能。
