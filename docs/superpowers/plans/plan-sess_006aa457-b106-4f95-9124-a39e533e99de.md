# Burp-Copilot：面向渗透初学者的 AI 引导式渗透桌面应用 · 完整方案

## 一、产品定位

面向"已获授权但不知从何下手"的渗透初学者：内置 MITM 代理抓取目标流量，云端 AI（用户自带 Key）对流量进行分析与讲解，动态生成**渗透任务树**一步步引导操作，所有结论附带 OWASP/CWE 知识卡片、置信度和人工验证步骤。

**设计红线**（贯穿全部功能）：
- 人在回路：AI 只做分析、解释、建议，不自动对目标发起攻击；所有验证动作由用户手动执行
- 误报素养：每个 AI 结论必须带置信度 + 推理过程 + "如何手动验证"步骤
- 授权声明：首次启动强制阅读并确认授权使用声明；目标域名需加入 Scope 才拦截

## 二、核心功能清单（综合竞品调研）

| # | 模块 | 功能 | 参考来源 |
|---|------|------|---------|
| 1 | MITM 代理 | HTTP/HTTPS 拦截、CA 证书生成与安装引导、Scope 过滤、WebSocket 记录 | Caido / Burp |
| 2 | 流量工作台 | 请求/响应表格、方法+状态+类型过滤、类 HTTPQL 搜索、请求详情查看器、重发（Repeater） | Caido HTTPQL / Burp Repeater |
| 3 | 被动规则引擎 | 本地轻量规则对流量自动打标（敏感参数、错误堆栈、可疑端点、明文密码、JWT 等），AI 分析前的初筛 | Caido Passive Workflows |
| 4 | AI 分析引擎 | 选中请求 → AI 解释接口作用、可疑参数、可能漏洞类型（OWASP 分类 + 置信度 + 推理 + 验证步骤）；提示词模板可定制，占位符注入 `{REQUEST}`/`{RESPONSE}` 等 | burpgpt / Burp AI |
| 5 | 渗透任务树 | AI 基于已收集流量生成动态任务树（侦察→测试→利用验证），节点状态：待做/进行中/完成/受阻；交互命令：`下一步`/`为什么`/`换个思路`/`展开子任务`；图形化展示 | PentestGPT PTT / Deciduous |
| 6 | 知识卡片 | 每个发现挂接 OWASP Top 10 / CWE 讲解（原理、危害、经典成因、修复建议），中文友好 | Strix / Vulnhuntr 报告结构 |
| 7 | 会话与复盘 | 项目制（一个授权目标 = 一个项目），SQLite 持久化流量/分析/任务树，会话恢复与回放 | PentestGPT / hackingBuddyGPT |
| 8 | 学习报告 | 一键生成 Markdown 报告：发现列表（含复现步骤、修复建议）+ 渗透过程时间线 | Burp AI / Strix |
| 9 | 设置中心 | API Key/Base URL/模型选择（OpenAI 兼容接口：DeepSeek、通义、Kimi 等）、代理端口、Scope、隐私开关（可全局禁用 AI） | burpgpt / Caido BYO-model |

## 三、技术架构

```
┌─────────────────────────────────────────────────┐
│  Tauri 2 前端 (Vue 3 + Element Plus + Pinia)     │
│  ├─ 流量表格 / 请求详情 / Repeater               │
│  ├─ 任务树可视化 (vue-flow / vis-network)        │
│  ├─ AI 对话面板 / 知识卡片 (Markdown 渲染)       │
│  └─ 设置 / 项目管理                              │
├────────────── Tauri Commands/Events ────────────┤
│  Rust 后端 (tokio 异步)                          │
│  ├─ proxy 模块: hudsucker (hyper+rustls+rcgen)   │
│  │   MITM 代理，拦截 → 存储 → 事件推送前端        │
│  ├─ rules 模块: 被动规则引擎 (regex/heuristic)   │
│  ├─ ai 模块: LLM 客户端 (reqwest, OpenAI 兼容)   │
│  │   ├─ 提示词模板系统 (占位符注入)              │
│  │   ├─ 请求分析器 (结构化 JSON 输出 + 校验)      │
│  │   └─ 任务树规划器 (PTT 生成/更新)             │
│  ├─ tree 模块: 任务树状态机 (增删改/状态流转)    │
│  ├─ storage: rusqlite (项目/流量/分析/树/设置)   │
│  └─ cert 模块: CA 生成/导出/平台信任引导         │
└─────────────────────────────────────────────────┘
```

**关键 crate 选型**：
- MITM 代理：`hudsucker`（hyper 1.x + rustls + rcgen，Rust 生态成熟方案，避免手写 TLS 拦截）
- 异步运行时：`tokio`；数据库：`rusqlite`（bundled）；HTTP 客户端：`reqwest`（调 LLM API）
- 序列化：`serde`/`serde_json`；LLM 结构化输出用 JSON Schema 约束 + 解析失败重试
- Tauri 2：`tauri-plugin-store`（设置）、事件系统做流量实时推送

**前端选型**：Vue 3 + Vite + Element Plus + Pinia + vue-flow（任务树）+ markdown-it（知识卡片/AI 回复渲染）

## 五、分阶段实施路线（完整架构、分批交付）

**Phase 0 · 骨架**（0.5~1 天）
- 初始化 Tauri 2 + Vue 3 工程、SQLite schema、设置页（API Key 存储）、授权声明弹窗
- 验收：`pnpm tauri dev` 起空壳，设置可保存

**Phase 1 · 代理与流量**（核心基建，优先打通）
- CA 证书生成/导出 + Windows 信任安装引导页
- hudsucker 代理：拦截 → 解析 → 存库 → Tauri Event 推送
- 流量表格 + 详情查看器 + 基础过滤 + Scope 设置
- 验收：浏览器走代理访问 HTTPS 站点，流量实时出现在表格中

**Phase 2 · AI 分析引擎**
- LLM 客户端（OpenAI 兼容，超时/重试/token 截断控制）
- 提示词模板系统（占位符 `{REQUEST}` `{RESPONSE}` `{URL}` `{METHOD}`，内置中文模板）
- 请求分析：结构化输出（接口用途/可疑参数/漏洞假设×N{类型,OWASP,置信度,推理,验证步骤}）
- 被动规则引擎（10~15 条内置规则先行）+ AI 结果以 Finding 形式展示
- 验收：选中登录请求，AI 输出结构化分析并解释为什么可能存在漏洞

**Phase 3 · 渗透任务树**
- 任务树数据模型与状态机；AI 规划器（基于流量摘要生成初始树 + 增量更新）
- vue-flow 可视化 + 节点详情面板（做什么/为什么/怎么做/验证标准）
- 交互：下一步/为什么/换个思路/手动标记状态；树与 Finding 双向关联
- 验收：导入一段流量后生成任务树，可交互推进

**Phase 4 · 知识库与报告**
- 内置 OWASP Top 10 + 常见 CWE 中文知识卡片（Markdown 资源文件）
- Repeater（手动改包重发，配合验证步骤）
- Markdown 学习报告导出
- 验收：完整走通 抓包→分析→树引导→验证→出报告 闭环

**Phase 5 · 打磨**
- 会话回放、性能（大流量量分页/虚拟滚动）、token 用量统计与成本提示、打包签名

## 六、关键风险与对策

1. **TLS 证书信任**：用户装根证书是最大门槛 → 做图文引导页 + 一键导出 + 检测代理连通性的自检向导
2. **AI 误报**：强制输出置信度和验证步骤，UI 上 Finding 默认"待验证"状态，验证后才可标记确认
3. **Token 成本**：流量摘要做截断与去敏；任务树规划基于摘要而非全量流量；显示用量统计
4. **合规**：启动授权声明、Scope 白名单机制、AI 不自动执行攻击动作；README 明确仅用于授权测试/学习
5. **Windows 平台细节**：证书安装需管理员权限提示；代理设置引导用户手动或用 `netsh`/系统代理 API（可选增强）

## 七、实施方式

按 Phase 0→5 顺序实现，每个 Phase 完成即验收一项再继续。全部代码从零编写（当前为空目录）。
